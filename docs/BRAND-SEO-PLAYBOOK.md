**Primary audiences:** technical hiring managers and Staff/Principal engineers; AI/ML researchers; engineers evaluating production architectures; technical product leaders; curious advanced practitioners.

- Branded: `Bilwasiva Basu Mallick`, `Bilwasiva AI scientist`, `Bilwasiva machine learning`, `Bilwasiva GitHub`, `Bilwasiva articles`.

Use these as natural topic clusters, never as keyword stuffing. Answer practical questions and cite original research.

## Publishing system: practical cadence

**Each substantial technical article:**
- Choose a specific search question and write an original answer with intuition, math, implementation, failure modes, and references.
- Write a descriptive title and a short unique meta description. Add internal links to one earlier article and the relevant topic hub.
- Include a clear main visual with meaningful alt text. Compress assets without harming text legibility.
- Check every code sample and clearly label simulations, approximations, extrapolations, and research limitations.
- Cross-post a *short* LinkedIn hook with a link to the canonical article. Adapt the format for Medium rather than creating duplicate competing canonicals.

**Weekly:** Publish or promote 1 high-value piece, add 2–3 informed replies to relevant technical discussions, and revisit reader questions that suggest future articles.

**Monthly:** Refresh one older article, improve internal linking, compare Search Console queries and landing pages, and identify which topics generate qualified conversations.

**Quarterly:** Update the About page, public projects, resume links, GitHub pins, and any professional-role descriptions.

## Metrics dashboard: track without inventing data

| Goal | Metric | Source | Review |
|---|---|---|---|
| Brand search visibility | Impressions and clicks for branded queries | Search Console | Monthly |
| Topic discovery | Non-branded search impressions/clicks and CTR | Search Console | Monthly |
| Search performance | Search position distribution (directional) | Search Console | Monthly |
| Reader engagement | Engaged sessions / returning readers (if configured) | Analytics | Monthly |
| Content distribution | LinkedIn impressions, link clicks, meaningful comments | LinkedIn analytics | Per post |
| Business impact | Relevant inbound recruiter, collaborator, or research inquiries | Email/LinkedIn | Monthly |
| Technical quality | PageSpeed/Core Web Vitals trends | PageSpeed / Search Console | Quarterly |

**Interpreting results:** Google Search Console includes sampled/lagged information and positions are contextual. Favor sustained trend improvements over day-to-day noise. Avoid assuming that one viral post equals durable professional impact.

## Suggested 90-day focus

**Days 1–30:** Validate sitemap and indexing. Audit link cards and improve page performance. Create 3 cornerstone topic hubs: LLM systems, agent systems, and physical AI. Connect consistent social bios and featured projects.

**Days 31–60:** Publish applied case studies or reproducible notes (with permissions and confidentiality respected). Improve existing high-impression/low-CTR pages based on real query data. Contribute thoughtful summaries in relevant engineering communities.

**Days 61–90:** Expand internal clusters; add an optional email newsletter only if you can reliably maintain it; measure inbound qualified conversations; iterate content and homepage CTAs using actual evidence.

## Safety, professionalism, and trust

- Never invent projects, endorsements, employer metrics, awards, research acceptance, or user testimonials.
- Separate educational simulations from deployed systems.
- Avoid confidential or proprietary employer details and anything not authorized for public disclosure.
- Never bulk-spam communities or manufacture engagement. Genuine, technically useful work creates stronger long-term reputation.
- Keep the site accessible, responsive, and fast. Ranking algorithms and external platform distribution cannot be controlled by this repository.
